# Пульс — агрегатор новостей

Python-сервис с веб-лентой, настройками RSS/Atom-источников, SQLite, автоматическим сбором и Telegram-дайджестом. Интерфейс на русском, адаптирован для телефона.

## Запуск

Python 3.11+; команды выполнять из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn main:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000. **Настройки → Источники новостей**: введите URL RSS/Atom или сайта, нажмите «Добавить источник». Сайт должен объявлять RSS через `link rel="alternate"`. Поле поиска фильтрует добавленные источники по названию и адресу. Источники можно отключать и удалять без перезапуска; сохранённые статьи остаются. Для Telegram вставьте `https://t.me/channel_name`, `https://t.me/s/channel_name`, ссылку на пост или `@channel_name`. Сервис читает последние доступные текстовые посты из публичного веб-просмотра, без авторизации. Закрытые каналы, приглашения, недоступные для веб-просмотра каналы и посты только с медиа не поддерживаются. История целиком не загружается; если между проверками опубликовано больше постов, чем видно на публичной странице, часть может быть пропущена. Изменения HTML Telegram могут потребовать обновления сборщика.

При первом старте автоматически подключаются:
- Хабр: https://habr.com/ru/rss/articles/?fl=ru
- Hacker News: https://news.ycombinator.com/rss

Первый сбор запускается при старте, далее — каждые 30 минут. Ошибки видны в настройках и логе. Сервис должен оставаться запущенным. Запускайте **один worker**, иначе фоновые задачи будут дублироваться. Это личный локальный сервис без авторизации; для общего доступа сначала добавьте аутентификацию и HTTPS.

## Настройки окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| DATABASE_PATH | data/news.sqlite3 | Путь к SQLite |
| COLLECT_MINUTES | 30 | Интервал сбора |
| DIGEST_HOUR / DIGEST_MINUTE | 9 / 0 | Время дайджеста |
| TIMEZONE | Europe/Moscow | Часовой пояс |
| TELEGRAM_BOT_TOKEN | пусто | Токен бота |
| TELEGRAM_CHAT_ID | пусто | Единственный получатель |

Изменения `.env` требуют перезапуска; изменения источников применяются сразу.

## Telegram

1. Создайте бота через @BotFather и получите токен.
2. Напишите боту `/start`.
3. Узнайте ID чата через метод `getUpdates` Bot API до запуска сервиса.
4. Укажите токен и ID в локальном `.env`, перезапустите сервис.

Отправка: ежедневно по расписанию, кнопкой в настройках или командой `/digest` из разрешённого чата. Без токена веб-лента и сбор работают, отправка отключена. Бот использует polling; webhook для этого токена должен быть выключен. Не запускайте второй потребитель getUpdates.

До 30 новых материалов за запуск, кратким нумерованным списком с заголовками, описаниями и ссылками. Длинный список разбивается на сообщения в пределах лимита Telegram. Успешные отправки отмечаются после каждого сообщения, оставшиеся попадут в следующий запуск. При неопределённом сетевом результате или остановке между отправкой и записью в SQLite возможна повторная доставка: Bot API не предоставляет идемпотентный sendMessage. Дедупликация хранения обеспечивается уникальными индексами URL и нормализованного заголовка + источника для RSS. Для Telegram ключ — идентификатор поста: разные публикации с одинаковым началом сохраняются отдельно. URL очищаются от UTM, fbclid, gclid и фрагментов. `created_at` — дата публикации (UTC, при отсутствии — дата получения), `collected_at` — дата загрузки.

## Проверки

```bash
python -m pytest -q
```

Покрыты дедупликация, отказ одного источника, разбор RSS, управление источниками, запрет межсайтовых изменений и учёт отправки. Внешние запросы в тестах заменены фикстурами; реальные данные и лог находятся в `examples/`. Проверку реальной доставки в Telegram выполняйте после настройки собственного бота.

## Структура

- `collectors/` — HTTP, RSS/Atom, публичные Telegram-каналы, поиск RSS на сайте, очистка текста.
- `database/` — схема SQLite и подключение.
- `services/` — сбор, дедупликация, обработка ошибок.
- `scheduler/` — APScheduler 3: сбор, дайджест, команды бота.
- `bot/` — Telegram Bot API и контроль отправки.
- `static/` — веб-интерфейс без сборки Node.js.
- `main.py` — FastAPI и API интерфейса.

Использованы официальные API: [APScheduler](https://apscheduler.readthedocs.io/en/3.x/userguide.html), [Telegram Bot API](https://core.telegram.org/bots/api), [FastAPI](https://fastapi.tiangolo.com/).

## Docker

```bash
cp .env.example .env
# При необходимости заполните Telegram-настройки.
docker compose up --build -d
```

Адрес тот же: http://127.0.0.1:8000. SQLite сохраняется в именованном томе `news-data`. Остановка: `docker compose down` (без `-v`, чтобы сохранить базу).

Если локальный Python не находит системные сертификаты macOS, установите сертификаты для своей сборки Python либо укажите `SSL_CERT_FILE=/etc/ssl/cert.pem` в `.env`, а для установки пакетов используйте `pip install --cert /etc/ssl/cert.pem -r requirements.txt`. Проверка TLS не отключается.
